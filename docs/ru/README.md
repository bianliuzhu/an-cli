# an-cli

# Обзор функций

> an-cli — это CLI-инструмент для фронтенда, включающий следующие команды:
>
> - Команда `anl type`: CLI-инструмент для автоматической генерации определений типов TypeScript и функций API-запросов на основе Swagger JSON.
> - Команда `anl lint`: Генерирует конфигурации eslint, stylelint, prettier, commitLint, VSCode для проектов react или vue
> - Команда `anl git`: Генерирует локальную конфигурацию git с опциональными функциями: создание стандартных веток gitflow, темы сообщений git commit, конфигурация пользовательских команд git

# Особенности функций

- `anl type`
  - 🚀 Автоматически парсит Swagger JSON документы
  - 📦 Генерирует файлы определений типов TypeScript
  - 🔄 Генерирует типобезопасные функции API-запросов
  - 🎯 Поддерживает параметры пути, запроса и тела запроса
  - 📝 Автоматически генерирует определения типов enum
  - 🎨 Поддерживает форматирование кода
  - ⚡️ Поддерживает загрузку файлов
  - 🛠 Настраиваемые опции генерации кода
  - 🌐 Поддерживает конфигурации нескольких Swagger серверов
  - 🔧 Поддерживает HTTP методы OPTIONS, HEAD, SEARCH и другие

- `anl lint`
  - 🔍 Настройка различных инструментов линтинга в один клик
  - 🎨 Автоматизация конфигурации ESLint
  - 🎯 Конфигурация форматирования Prettier
  - 🔄 Стандарты коммитов CommitLint
  - 📦 Конфигурация редактора VSCode

- `anl git`
  - 🔍 Множественные опциональные функции для установки
  - 🎨 Создание стандартных веток git flow
  - 🎯 Автоматическая настройка тем, соответствующих стандартам CommitLint
  - 🔄 Предоставляет конфигурацию пользовательских команд git и точки входа
  - 📦 Автоматическая генерация с нулевой конфигурацией

> [!TIP]
>
> 1. Если используете впервые и не знаете, какой результат будет получен, рекомендуется сначала выполнить команду, посмотреть, какие изменения произойдут в проекте, затем в сочетании с документацией дополнительно изменить конфигурацию, снова сгенерировать, и в итоге достичь желаемого результата
> 2. Или следуйте шагам ниже по порядку, и вы получите результат
> 3. Пожалуйста, выполняйте команды `anl type`, `anl lint`, `anl git` в корневой директории проекта

## Инструкция по использованию команды `anl type`

- При **первом** выполнении команды `anl type` в _корневой директории проекта_ автоматически создается файл конфигурации с именем `an.config.json` (можно создать вручную) для инициализации шаблона конфигурации.

- При выполнении команды `anl type` ищется файл конфигурации `an.config.json` в корневой директории пользовательского проекта, читается его конфигурационная информация и генерируются соответствующие обертки axios, конфигурация, список интерфейсов, интерфейсы запросов и TS-типы параметров и ответов каждого интерфейса запроса

- Элементы конфигурации в файле конфигурации можно свободно изменять

- О файле конфигурации `an.config.json`
  - Файл конфигурации должен находиться в корневой директории проекта

  - Имя файла конфигурации нельзя изменять

  - Подробное описание параметров см. в разделе [Подробное описание конфигурационного файла](#подробное-описание-конфигурационного-файла)

- Обновите файл конфигурации согласно своим потребностям, затем снова выполните команду `anl type`, и она сгенерирует соответствующую информацию о типах согласно указанной конфигурационной информации в файле конфигурации

- Если файлы 'config.ts', 'error-message.ts', 'fetch.ts', 'api-type.d.ts' существуют, они не будут генерироваться повторно

-

> [!NOTE]
>
> Если не знаете эти конфигурации, можно сначала выполнить команду anl type, сначала сгенерировать типы, затем проверить директорию проекта, в сочетании с описанием элементов конфигурации, скорректировать элементы конфигурации, снова сгенерировать, постепенно проверить роль элементов конфигурации, завершить окончательную конфигурацию

#### Соответствие элементов конфигурации и генерируемых файлов

> Структура файлов создается на основе конфигурационного файла, пометка **неконтролируемый** означает: эта папка и ее файлы генерируются автоматически и не контролируются элементами конфигурации

```
project/
├── apps/
│   ├── types/               		# Указывается элементом конфигурации saveTypeFolderPath
│   │   ├── models/          				# Все файлы определений типов (не включая типы enum) неконтролируемые
│   │   ├── connectors/      				# Определения типов API (файлы определений интерфейсов) неконтролируемые
│   └── api/                 		# Файлы запросов: указывается элементом конфигурации saveApiListFolderPath
│   │    └── index.ts        				# Список функций API-запросов (один сервер или первый сервер) неконтролируемый
│   │    └── op.ts           				# Файлы списка API других серверов при использовании нескольких серверов неконтролируемые
│   │    └── api-type.d.ts      		# Файл определений типов запросов неконтролируемый
│   │    └── config.ts       				# Конфигурация запросов, перехватчиков ответов, конфигурация запросов неконтролируемая
│   │    └── error-message.ts   		# Системные сообщения об ошибках неконтролируемые
│   │    ├── fetch.ts        				# Обертка axios запросов, можно заменить на fetch неконтролируемая
│   └── enums/               		# Определения типов данных enum: указывается элементом конфигурации saveEnumFolderPath
```

### Описание особенностей

#### Приоритет конфигурации

Инструмент поддерживает глобальную конфигурацию и конфигурацию уровня сервера, следуя следующим правилам приоритета:

**Приоритет: Конфигурация уровня сервера > Глобальная конфигурация > Значения по умолчанию**

Следующие элементы конфигурации поддерживают переопределение глобальной конфигурации на уровне сервера:

- `dataLevel`: Уровень данных возврата интерфейса
- `parameterSeparator`: Разделитель для имен API и имен типов
- `includeInterface`: Список включаемых интерфейсов
- `excludeInterface`: Список исключаемых интерфейсов
- `requestPathPrefix`: Префикс пути запроса
- `stripPathPrefix`: Общий префикс URL
- `headers`: Конфигурация заголовков запроса

**Пример:**

```json
{
	"dataLevel": "serve",
	"parameterSeparator": "_",
	"swaggerConfig": [
		{
			"url": "http://api1.example.com/swagger.json",
			"dataLevel": "data",
			"apiListFileName": "api1.ts"
		},
		{
			"url": "http://api2.example.com/swagger.json",
			"apiListFileName": "api2.ts"
		}
	]
}
```

В приведенной выше конфигурации:

- `api1.ts` использует `dataLevel: "data"` (конфигурация уровня сервера)
- `api2.ts` использует `dataLevel: "serve"` (глобальная конфигурация)
- Оба сервера используют `parameterSeparator: "_"` (глобальная конфигурация)

#### Разбор типов

- Поддержка всех типов данных спецификации OpenAPI 3.0
- Автоматическая обработка сложных вложенных типов
- Поддержка массивов, объектов, enum и других типов
- Автоматическая генерация комментариев к интерфейсам

#### Генерация enum

Инструмент поддерживает два режима генерации enum, контролируемые через конфигурацию `enmuConfig.erasableSyntaxOnly`:

**Традиционный режим enum** (`enmuConfig.erasableSyntaxOnly: false`, значение по умолчанию):

```typescript
export enum Status {
	Success = 'Success',
	Error = 'Error',
	Pending = 'Pending',
}
```

**Режим константного объекта** (`enmuConfig.erasableSyntaxOnly: true`):

```typescript
export const Status = {
	Success: 'Success',
	Error: 'Error',
	Pending: 'Pending',
} as const;

export type StatusType = (typeof Status)[keyof typeof Status];
```

> **Зачем использовать режим константного объекта?**
> Когда в TypeScript `compilerOptions.erasableSyntaxOnly` установлен в `true`, код может использовать только стираемый типовый синтаксис. Традиционный `enum` генерирует рантайм-код, в то время как константный объект является чисто типовым и полностью стирается после компиляции. Это обеспечивает совместимость с инструментами сборки, требующими только типовой синтаксис.

**Использование в типах:**

```typescript
// Традиционный режим enum
interface User {
	status: Status; // Используйте enum напрямую как тип
}

// Режим константного объекта
interface User {
	status: StatusType; // Используйте сгенерированный тип с суффиксом 'Type'
}
```

#### Конфигурация уровня данных (dataLevel)

`dataLevel` используется для настройки уровня извлечения данных возврата интерфейса, поддерживает три варианта:

1. **`'serve'` (по умолчанию)**: Извлекает поле `data` из ответа сервера

   ```typescript
   // Сервер возвращает: { code: 200, message: 'success', data: { id: 1, name: 'user' } }
   // Функция возвращает: { id: 1, name: 'user' }
   ```

2. **`'data'`**: Извлекает поле `data.data` (для сценариев с вложенными данными)

   ```typescript
   // Сервер возвращает: { data: { code: 200, data: { id: 1, name: 'user' } } }
   // Функция возвращает: { id: 1, name: 'user' }
   ```

3. **`'axios'`**: Возвращает полный объект ответа axios
   ```typescript
   // Сервер возвращает: { code: 200, message: 'success', data: { id: 1, name: 'user' } }
   // Функция возвращает: { code: 200, message: 'success', data: { id: 1, name: 'user' } }
   ```

**Пример конфигурации:**

```json
{
	"dataLevel": "serve",
	"swaggerConfig": [
		{
			"url": "http://api1.example.com/swagger.json",
			"dataLevel": "data"
		}
	]
}
```

> **Примечание**: Конфигурация `dataLevel` на уровне сервера переопределит глобальную конфигурацию.

#### Форматирование кода

Инструмент поддерживает настраиваемые параметры форматирования кода, контролируемые конфигурацией `formatting`:

**Пример конфигурации:**

```json
{
	"formatting": {
		"indentation": "\t",
		"lineEnding": "\n"
	}
}
```

**Описание конфигурации:**

- `indentation`: Символ отступа кода
  - `"\t"`: Использовать отступ Tab (по умолчанию)
  - `"  "`: Использовать отступ в 2 пробела
  - `"    "`: Использовать отступ в 4 пробела
- `lineEnding`: Тип разрыва строки
  - `"\n"`: LF (стиль Linux/macOS, рекомендуется)
  - `"\r\n"`: CRLF (стиль Windows)

**Примечание:** Если в проекте настроен Prettier, сгенерированный код автоматически будет отформатирован с помощью Prettier, и конфигурация `formatting` может быть переопределена Prettier.

#### Загрузка файлов

При обнаружении типа загрузки файлов автоматически добавляются соответствующие заголовки запроса:

```typescript
export const uploadFile = (params: UploadFile.Body) =>
	POST<UploadFile.Response>('/upload', params, {
		headers: { 'Content-Type': 'multipart/form-data' },
	});
```

#### Обработка ошибок

Инструмент имеет встроенный совершенный механизм обработки ошибок:

- Подсказки об ошибках разбора
- Предупреждения о неудачной генерации типов
- Обработка исключений при записи файлов

#### Фильтрация интерфейсов

Инструмент поддерживает фильтрацию генерируемых интерфейсов через конфигурацию:

1. Включение определенных интерфейсов
   - Укажите нужные интерфейсы через элемент конфигурации `includeInterface`
   - Будет сгенерирован только указанный в конфигурации интерфейс
   - Формат конфигурации: массив объектов, содержащих `path` и `method`

2. Исключение определенных интерфейсов
   - Укажите интерфейсы для исключения через элемент конфигурации `excludeInterface`
   - Будет сгенерирован весь интерфейс, кроме указанного в конфигурации
   - Формат конфигурации: массив объектов, содержащих `path` и `method`

Пример конфигурации: эта конфигурация в `an.config.json`

```json
{
	"includeInterface": [
		{
			"path": "/api/user",
			"method": "get"
		}
	],
	"excludeInterface": [
		{
			"path": "/api/admin",
			"method": "post"
		}
	]
}
```

Примечание: `includeInterface` и `excludeInterface` нельзя использовать одновременно, если они настроены одновременно, будет приоритетно использоваться `includeInterface`.

#### Поддержка нескольких Swagger серверов

Инструмент поддерживает конфигурацию нескольких Swagger серверов, каждый сервер может быть настроен независимо:

- **Один сервер**: `swaggerConfig` может быть напрямую заполнен объектом
- **Несколько серверов**: `swaggerConfig` использует формат массива, каждый сервер должен настроить уникальный `apiListFileName`

**Как это работает:**

- API первого сервера будут сгенерированы в указанный `apiListFileName` (по умолчанию `index.ts`)
- API последующих серверов будут добавлены в их соответствующие файлы `apiListFileName`
- Определения типов и enum будут объединены в единую папку, чтобы избежать дублирования

**Конфигурация уровня сервера:**

Каждый сервер поддерживает независимую настройку следующих параметров. Если не установлено, будет использоваться глобальная конфигурация:

- `dataLevel` - Уровень данных возврата интерфейса
- `parameterSeparator` - Разделитель для имен API и имен типов
- `includeInterface` - Список включаемых интерфейсов
- `excludeInterface` - Список исключаемых интерфейсов
- `requestPathPrefix` - Префикс пути запроса

#### Префикс пути (requestPathPrefix)

`requestPathPrefix` используется для автоматического добавления префикса ко всем путям API-запросов, что особенно полезно в следующих сценариях:

1. **Сценарии обратного прокси**: Когда серверные службы перенаправляются через обратный прокси
2. **API-шлюз**: Единообразное добавление префикса шлюза к путям
3. **Конфигурация для нескольких сред**: Использование разных префиксов путей для разных сред

**Пример использования:**

```json
{
	"swaggerConfig": [
		{
			"url": "http://api.example.com/swagger.json",
			"requestPathPrefix": "/forward",
			"apiListFileName": "api.ts"
		}
	]
}
```

**Эффект:**

Путь `/api/user/list`, определенный в Swagger, будет сгенерирован как:

```typescript
export const apiUserListGet = (params: ApiUserList_GET.Query) => GET<ApiUserList_GET.Response>('/forward/api/user/list', params);
```

**Отличие от stripPathPrefix:**

- `stripPathPrefix`: Используется для удаления общего префикса из путей интерфейса (влияет только на сгенерированные имена функций)
- `requestPathPrefix`: Используется для добавления префикса к фактическим путям запроса (влияет на URL-адреса запросов во время выполнения)

**Пример конфигурации:**

```json
{
	"swaggerConfig": [
		{
			"url": "http://api1.example.com/swagger.json",
			"apiListFileName": "api1.ts",
			"stripPathPrefix": "/api/v1",
			"requestPathPrefix": "/forward",
			"dataLevel": "serve",
			"parameterSeparator": "_",
			"headers": {
				"Authorization": "Bearer token1"
			},
			"includeInterface": [
				{
					"path": "/api/v1/users",
					"method": "get"
				}
			]
		},
		{
			"url": "http://api2.example.com/swagger.json",
			"apiListFileName": "api2.ts",
			"stripPathPrefix": "/api/v2",
			"dataLevel": "data",
			"headers": {
				"Authorization": "Bearer token2"
			}
		}
	]
}
```

**Примечания по миграции:**

- Старая конфигурация (`swaggerJsonUrl`, `stripPathPrefix`, `headers`) все еще совместима
- Инструмент автоматически обнаружит старую конфигурацию и предложит способы миграции
- Рекомендуется мигрировать на новую конфигурацию `swaggerConfig` для большей гибкости

#### Поддержка HTTP методов

Инструмент поддерживает следующие HTTP методы:

- `GET` - Получение ресурсов
- `POST` - Создание ресурсов
- `PUT` - Обновление ресурсов (полная замена)
- `PATCH` - Обновление ресурсов (частичное обновление)
- `DELETE` - Удаление ресурсов
- `OPTIONS` - Предварительные запросы
- `HEAD` - Получение заголовков ответа
- `SEARCH` - Поисковые запросы

Все методы поддерживают типобезопасные определения типов параметров и ответов.

### Меры предосторожности

1. Убедитесь, что адрес документа Swagger JSON доступен
2. Пути в файле конфигурации должны быть относительными путями к корневой директории проекта
3. Генерируемые файлы будут перезаписывать существующие файлы с тем же именем (но `config.ts`, `error-message.ts`, `fetch.ts`, `api-type.d.ts` не будут перезаписаны, если они уже существуют)
4. Рекомендуется добавлять генерируемые файлы в систему контроля версий
5. При использовании нескольких Swagger серверов убедитесь, что `apiListFileName` каждого сервера уникален, чтобы избежать перезаписи файлов
6. При конфигурации нескольких серверов определения типов и enum будут объединены. Если разные серверы имеют типы с одинаковыми именами, могут возникнуть конфликты
7. Конфигурация уровня сервера (`dataLevel`, `parameterSeparator`, `includeInterface`, `excludeInterface`, `requestPathPrefix`) переопределит глобальную конфигурацию
8. `includeInterface` и `excludeInterface` нельзя настраивать одновременно. Если оба настроены, приоритет будет у `includeInterface`

### Часто задаваемые вопросы

1. **Не удается отформатировать файлы типов**
   - Проверьте, установлен ли prettier
   - Убедитесь, что в корневой директории проекта есть файл конфигурации prettier
   - Проверьте правильность конфигурации `formatting`

2. **Неверный путь импорта в функциях запросов**
   - Проверьте, правильно ли настроен `requestMethodsImportPath`
   - Убедитесь, что файл методов запросов существует

3. **Когда использовать `requestPathPrefix`?**
   - Когда ваши API необходимо получать через обратный прокси или шлюз
   - Например: Swagger определяет `/api/user`, но фактический запрос должен быть `/gateway/api/user`
   - Установите `requestPathPrefix: "/gateway"` для достижения этого

4. **В чем разница между `stripPathPrefix` и `requestPathPrefix`?**
   - `stripPathPrefix`: Удаляет префикс из путей интерфейса, влияет только на сгенерированные имена функций
     - Пример: `/api/user/list` после удаления `/api`, имя функции становится `userListGet`
   - `requestPathPrefix`: Добавляет префикс к путям запроса, влияет на фактические URL запросов
     - Пример: `/api/user/list` после добавления `/forward`, URL запроса становится `/forward/api/user/list`

5. **Как настроить разные `dataLevel` для нескольких серверов?**

   ```json
   {
   	"dataLevel": "serve",
   	"swaggerConfig": [
   		{
   			"url": "http://old-api.com/swagger.json",
   			"dataLevel": "axios",
   			"apiListFileName": "old-api.ts"
   		},
   		{
   			"url": "http://new-api.com/swagger.json",
   			"apiListFileName": "new-api.ts"
   		}
   	]
   }
   ```

   - `old-api.ts` использует `dataLevel: "axios"`
   - `new-api.ts` использует глобальный `dataLevel: "serve"`

6. **Как генерировать только определенные интерфейсы?**
   - Используйте конфигурацию `includeInterface`:
     ```json
     {
     	"swaggerConfig": [
     		{
     			"url": "http://api.com/swagger.json",
     			"includeInterface": [
     				{ "path": "/api/user", "method": "get" },
     				{ "path": "/api/user/{id}", "method": "post" }
     			]
     		}
     	]
     }
     ```
   - Или используйте `excludeInterface` для исключения ненужных интерфейсов

7. **Что делать, если сгенерированные файлы перезаписаны?**
   - Файлы типа `config.ts`, `error-message.ts`, `fetch.ts`, `api-type.d.ts` генерируются только при их отсутствии
   - Файлы списков API и файлы типов регенерируются каждый раз
   - Рекомендуется добавлять сгенерированные файлы в систему контроля версий для удобного отслеживания изменений

# Инструкция по использованию команды `anl lint`

> Предоставляет функцию настройки различных инструментов линтинга для фронтенд-проектов в один клик, включая:
>
> - Проверку кода ESLint
> - Форматирование кода Prettier
> - Стандарты сообщений коммитов CommitLint
> - Конфигурацию редактора VSCode

### Способ использования

```bash
$ anl lint
```

После выполнения команды появится интерактивный интерфейс множественного выбора, где вы можете выбрать инструменты для установки:

```
? Select the linting tools to install (multi-select):
❯◯ ESLint - JavaScript/TypeScript linter
 ◯ Stylelint - CSS/SCSS/Less linter
 ◯ Commitlint - Git commit message linter
 ◯ Prettier - Code formatter
 ◯ VSCode - Editor settings
```

Используйте **пробел** для выбора/отмены выбора, **Enter** для подтверждения.

### Детали конфигурации

#### 1. Конфигурация ESLint

- Автоматическая установка необходимых зависимостей
- Поддержка фреймворков React/Vue (вам будет предложено выбрать фреймворк при выборе)
- Автоматическая генерация `.eslintrc.js` и `.eslintignore`
- Интеграция поддержки TypeScript

#### 2. Конфигурация Stylelint

- Автоматическая установка зависимостей stylelint
- Поддержка препроцессоров Less/Sass (вам будет предложено выбрать препроцессор при выборе)
- Генерация файла конфигурации `.stylelintrc.js`
- Интеграция поддержки Prettier

#### 3. Конфигурация Prettier

- Автоматическая установка зависимостей prettier
- Генерация файла конфигурации `.prettierrc.js`
- Конфигурация по умолчанию включает:
  - Ширина строки: 80
  - Отступы табуляцией
  - Использование одинарных кавычек
  - Скобки стрелочных функций
  - Другие стандарты стиля кода

#### 4. Конфигурация CommitLint

- Установка зависимостей commitlint
- Настройка git hooks husky
- Генерация `commitlint.config.js`
- Стандартизация сообщений git commit

#### 5. Конфигурация VSCode

- Создание `.vscode/settings.json`
- Конфигурация автоматического форматирования редактора
- Настройка инструмента форматирования по умолчанию
- Поддержка обновления существующих файлов конфигурации

### Примеры использования

1. **Установить только ESLint и Prettier**
   - Выберите ESLint и Prettier
   - Если выбран ESLint, вам будет предложено выбрать фреймворк (React/Vue)
   - После установки в вашем проекте будут `.eslintrc.js` и `.prettierrc.js`

2. **Полная конфигурация**
   - Выберите все опции
   - Завершите выбор фреймворка и препроцессора
   - В вашем проекте будет настроена полная система стандартов кода

# Команда `anl git`

### Обзор функций

- Через интерактивный множественный выбор применяет следующие возможности Git к текущему репозиторию:
  - Создание стандартных веток gitflow
    - Копирует `.gitscripts/`, `.gitconfig`, `.commit-type.cjs` в проект (только при отсутствии)
    - Добавляет права на выполнение для `.gitscripts/random-branch.sh`
    - Выполняет `git config --local include.path ../.gitconfig`
  - Автоматическая настройка темы commit subject
    - Копирует `.githooks/commit-msg` и устанавливает права на выполнение
    - Выполняет `git config core.hooksPath .githooks`
  - Пользовательские команды git
    - Добавляет `.gitattributes` в проект (только при отсутствии)

### Способ использования

```bash
$ anl git
```

В подсказке выберите одну или несколько функций. Файлы создаются только при отсутствии; существующие файлы сохраняются.

### Меры предосторожности

- Пожалуйста, запускайте в Git-репозитории.
- Если автоматически выполняемая git config не удалась, выполните вручную:

```bash
git config --local include.path ../.gitconfig
git config core.hooksPath .githooks
```
